# Verification Checkpoints

Systematic confirmation that each foundational layer is understood before advancing.

## Checkpoint Types

### Type 1: Direct confirmation
```
"Does that make sense so far?"
```
Wait for explicit yes/no. Do not assume silence = understanding.

### Type 2: Teach-back
```
"In your own words, what does [concept] mean?"
```
Most reliable signal. If they can rephrase it, they understand it.

### Type 3: Application check
```
"If [situation], what would [concept] do?"
```
Tests transfer. Ask them to apply the concept to a new scenario.

### Type 4: Connection check
```
"How does [concept] relate to [previous concept]?"
```
Tests integration across layers.

## Frequency Rules

- **After every atomic concept**: Type 1 (lightweight)
- **After every composite layer** (2+ atomic concepts combined): Type 2 or Type 3
- **Before the final synthesis**: Type 4
- **Never skip verification for the deepest foundational layer**

## Handling Responses

| User says | Action |
|---|---|
| "Yes" / "Got it" / "Makes sense" | Proceed (use Type 2 at next composite checkpoint) |
| "Not really" / "I don't get it" | Reframe with different analogy, then Type 1 again |
| Partial understanding | Identify the gap: "Which part is unclear?" then focus there |
| Silence / "Hmm" | Assume not clear. Offer: "Let me try explaining differently." |
| "I know this already" | Skip ahead: "Which part can we skip?" Accept their judgment |

## The Three-Strike Rule

If a user fails to demonstrate understanding after 3 attempts at the same level:

1. **First attempt**: Explain with a different analogy or modality
2. **Second attempt**: Ask what specifically is confusing
3. **Third attempt**: Suggest revisiting the previous layer — the gap may be one level down

After strike 3:
```
"It seems like something earlier is blocking this. Let's step back to [previous layer]
and make sure that's solid first."
```

## Confirming Readiness to Advance

Only advance when both conditions are met:
1. User explicitly confirms understanding (verbal or typed)
2. OR user demonstrates understanding through a correct teach-back or application
